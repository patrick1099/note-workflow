# Relationship and placement rules

Use these relationship labels:

- `前置知识`: the target is required to understand the current mechanism.
- `后续应用`: the target applies or extends the current mechanism.
- `来源与证据`: the target directly supports the adjacent statement.
- `相关案例`: the target records a real occurrence of the adjacent mechanism or
  risk.
- `普通相关`: a useful relation without one of the stronger directions.

Place each link in this order:

1. Convert an existing natural term into a Wiki link.
2. Add the link to the relevant sentence.
3. Add one short sentence at the end of the relevant paragraph.
4. Add a small related-note block at the end of the relevant section.
5. Use the document footer for broad whole-note relationships.
6. Route dense topic aggregation through an `index` note.
7. Omit the link when its reading value cannot be explained.

Allow body placement only when the target directly explains the concept,
mechanism, step, claim, evidence, or case at that anchor and the change does not
alter meaning.

Never insert links inside code blocks, raw logs, protocol frames, commands,
URLs, quotations, or evidence that must remain verbatim. Place an explanation
outside those blocks.

Use the smallest change:

1. Link existing words.
2. Append a short reference to an existing sentence.
3. Add one meaning-preserving sentence.
4. Move a sentence or paragraph only with explicit approval.

Do not rewrite unrelated prose, change claim strength, delete hand-written
links, or create causal language from a weak relation. Moving a duplicate footer
link into the body and deleting the old duplicate must be one atomic action.
